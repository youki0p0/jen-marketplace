# 絶対制約（AXIOM-0）: Claude のみで完結する

ユーザー指示（原文）:
「Jenの思想が『使用環境はClaudeのみで完結するエージェント』なのでそれだけは一貫した絶対的判断となるようにお願いします」

これは設計判断の**上位**に置く。他のどの原則（P1-P8）も、これに反する実装は選ばない。
性能・論文の裏付け・流行は、この制約を覆す理由にならない。

## 境界（v2・ユーザーの補足で訂正）

ユーザー補足（原文）:
「Claudeのみで完結するの意図の中にMCP等の道具は入っていないので道具はいちから作るよりも
適しているものを使用する方が遥かに建設的ではあると思います。Claude内から実行出来るので
あればMCP使用は合理的です」

**制約がかかるのは「知能」であって「道具」ではない。**

### ✗ 禁じられる（知能が Claude の外へ出る／Claude 内で作れない）
1. **Claude 以外のモデルに推論させること。** 他社LLM、ローカルLLM、学習済み分類器に判断を委ねる。
2. **学習・微調整を要する部品。** LoRA、報酬モデル、preference dataset、進化探索。
   Claude 内から実行できないので、そもそも成立しない。

### ✓ 許される（Claude 内から実行できる道具）
3. **MCP サーバ。** ブラウザ自動化、テスト実行、DB、git 等。**自作より既存を使う方を優先する。**
4. **外部コマンド・ライブラリ。** Claude Code の Bash から叩けるもの。
5. Claude Code のプラグイン面（agents/ skills/ commands/ hooks/ templates/）。

### ただし運用上の原則（公理ではなく設計判断）
6. **特定の MCP サーバや外部コマンドを「必須」にしない。** あれば使い、無ければ縮退する。
   理由は公理ではなく Jen の既存の約束:「以上。リポジトリに何も展開しません」。
   インストールが工事になった時点で Jen の良さが消える。
   → **hook 本体は stdlib のみで書く**（必ず動く下限）。道具はその上の任意層に置く。
7. 書き込み先は作業リポジトリ内の `.jen/` のみ。外部送信はしない（v3 からの監査済みの性質を維持）。

## この制約が設計を**良くする**点（偶然ではない）

Jain の結果は「ハーネスの最大の危険は**オーバーヘッド**」と言っている
（フロンティアで +約16倍のトークン、合否は不変）。
Claude のみ・stdlib のみ・外部サービスなしという制約は、**薄いハーネスを強制する**。
重い外部機構を足せないので、Jain が警告したコストが構造的に抑えられる。

また HALT の検証器が失格になったことで、代替は「極小の問いを haiku に聞く」になる。
これは P2（判定を極小に割る）をむしろ**徹底する**方向に働く。
制約が設計を一方向へ絞っている。


## 訂正の影響（道具が許されたことで設計が強くなった点）

コキエの教訓は「文字列 proof は偽造される → ファイルベースにせよ」だった。
ファイルベースは**偽造しにくい**が、エージェントが bash で書けば偽造**できる**
（コキエ自身も「完全な防御ではない」と書いている）。

道具（MCP・外部コマンド）が使えるなら、**より強い形**が取れる:
**ハーネス自身が実行して得た結果を証拠にする。**
- テストの終了コードを hook が捕まえる（エージェントの自己申告を経由しない）
- ブラウザ自動化の実行結果・スクリーンショット
- 実際の HTTP 応答

これはエージェントが**トークン出力では作れない**。証拠の強度が
「文字列（偽造自由）< ファイル（偽造に意図が要る）< **ハーネスが自分で実行して得た結果（偽造不能）**」
と上がる。Anthropic も Puppeteer で検収して「dramatically improved performance」と書いていた。

→ 証拠台帳の設計を「3段階の証拠強度」を持つ形に変える。
