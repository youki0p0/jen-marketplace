# Lessons Protocol (v3.3) — 過ちを繰り返さないための教訓台帳

目的: 失敗を「直して終わり」にせず、考察と解決策を `.jen/lessons.md` に資産化し、
同種タスクの委譲時に注入して再発を防ぐ。

## 1. 教訓の記載（失敗解決時・必須）

REJECTや障害が解決されたら、解決した担当（builder/debugger/deep-solver等）の
報告を基にPMOが `.jen/lessons.md` へ1エントリ追記する:

```markdown
## L-013 [tool_failure] npm testがCI環境変数不足で失敗
- 事象: T-009でテストが常時失敗。ローカルでは再現せず
- 考察(根本原因): CI環境に DATABASE_URL が未定義。
  確定: env依存 / 推測: 他の環境変数too / 未確認: staging環境
- 解決策: env.example追加＋CI設定にsecrets注入
- 再発防止ルール: テスト系タスクの委譲時は env.example と CI設定の環境変数を先に確認する
- 適用範囲: task_type=test,debug / 関連: T-009
```

規律:
- 考察は「確定 / 推測 / 未確認」を分ける。原因を断定できないまま閉じない
- 再発防止ルールは**1行・命令形・次の担当がそのまま従える粒度**で書く
- 表面的な対処（リトライで通った等）しかない場合は「根本原因未特定」と明記し、
  未解決教訓として残す

## 2. 教訓の注入（委譲前・必須）

PMOは委譲の前に `.jen/lessons.md` を確認し、task_type・失敗タイプが一致する
エントリの**再発防止ルールのみ**（最大3件）を委譲promptに含める:

```
過去の教訓(遵守):
- L-013: テスト系タスクではenv.exampleとCI環境変数を先に確認する
```

全文注入はしない（コンテキスト汚染）。ルール行だけでよい。

## 3. 再発の検知と昇格

- verifierは REJECT 時、失敗が既存教訓の再発防止ルール違反に該当するかを確認し、
  該当すれば `REJECT[<type>][再発:L-013]` とタグ付けする
- 再発タグが付いたら、PMOは board.md の失敗共有に ⚠️再発 として明示し、
  該当ルールを以後の同種委譲promptの**先頭に固定**する
- 同一教訓の再発が2回に達したら、教訓の書き方自体が悪い可能性を疑い、
  エントリを見直して再発防止ルールを具体化する（Human Gateに相談してよい）

## 4. 他の台帳との関係

- verification.md: 検収の生ログ（毎回） / lessons.md: 昇華された教訓（解決時のみ）
- routing-stats.json: 誰が失敗したか / lessons.md: なぜ失敗し、どう防ぐか
- board.md の「失敗共有(解決済み)」には lessons.md のエントリID（L-xxx）を残す
