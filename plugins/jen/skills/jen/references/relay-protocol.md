# Relay Protocol — メインセッションを伝言役に固定する（v3.8）

## なぜ

v3.7まで、`skills/jen/SKILL.md` はメインセッション自身をPMOとして振る舞わせていた。
つまりユーザー入力 → メインセッションが解釈・要約 → 各workerへ委譲、という
**伝言ゲーム**が常に1段挟まっていた。メインセッションの解釈が劣化した場合、
原文がどこにも残っていないため復旧手段が無い。

v3.8ではこれを反転させる:

- **メインセッション = 伝言役のみ**。解釈・分解・委譲・実装を一切しない。
- **jen-pmo = 唯一のオーケストレーター**。
- **ユーザー入力の原文を `.jen/inbox.md` に逐語で永続化**し、以後どの階層の
  agentも原文に立ち返れるようにする（伝言ゲームの解毒剤）。

## メインセッションに許された行為（これだけ）

1. ユーザー入力を**一字一句そのまま** `.jen/inbox.md` に追記する
   （要約・整形・翻訳・省略をしない。誤字もそのまま）。
2. `jen-pmo` を起動し、**その原文をそのまま**渡す。
3. `jen-pmo` の出力をユーザーへ返す（勝手に要約・脚色しない）。
4. **Human Gate の対人確認**（後述の構造的例外）。
5. `echo $CLAUDE_PLUGIN_ROOT` の解決（scoutはBashを持たないため）。

## メインセッションの禁止事項

- タスク分解、受入条件の作成、DAG化 → すべて jen-pmo の仕事
- worker（builder/frontend/test/…）への直接委譲
- 自分でコードを読む・書く・テストを実行する
- ユーザー入力を「要するに〜ですね」と言い換えて渡すこと（最大の禁止事項）

## 構造的例外: Human Gate

Claude Code はすべてのサブエージェントから `AskUserQuestion` を剥奪する。
つまり **jen-pmo はユーザーに直接質問できない**。したがって:

- jen-pmo は Human Gate に到達したら、**質問文をそのまま出力して停止**する。
- メインセッションはその質問文を**改変せずユーザーへ提示**し、
  ユーザーの回答を**逐語で** `.jen/inbox.md` へ追記してから jen-pmo を再起動する。

これはメインセッションに残る唯一の対話的責務であり、伝言役の範囲内である。

## ⚠️ 前提条件（必読・未検証）

この設計は **jen-pmo がサブエージェントを起動できること**に依存する。
Claude Code の仕様上、以下の制約がある:

1. `tools:` は許可リストなので、`jen-pmo` の `tools:` に **`Agent` を明記**する
   必要がある（v3.8で追加済み）。
2. インタラクティブセッションでは fork mode が既定でONのため、サブエージェントは
   **background 実行**になる。公式ドキュメントの「background subagent が保持する
   組み込みツール」一覧に `Agent` は**含まれていない**。
   一方で「サブエージェントは既定で3階層まで自分のサブエージェントを起動できる」
   とも記載されており、**記述が競合している**。Jen側では実機検証していない。

**したがって、導入したら最初に1回だけ次を確認すること**:

```
/jen:jen conduct  Goal: テスト。scoutにこのリポジトリのファイル数だけ数えさせて。
```

jen-pmo が scout へ委譲できていれば正常。委譲できず jen-pmo が自分で数え始めたら、
`Agent` が剥奪されている。その場合は次のいずれかで回避する:

```bash
export CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1   # サブエージェントを前景実行にする
```

これでも委譲できない場合、この環境では v3.8 の分離は成立しない。
`.jen/inbox.md` による原文保全だけは有効なので、SKILL.md の
「メインセッションがPMOを兼ねる」旧方式へ一時的に戻す判断は人間が行う。

## 原文保全（`.jen/inbox.md`）

伝言ゲーム対策の本体。メインセッションが追記し、**誰も編集しない**追記専用ログ。

```md
## [IN-003] 2026-08-28T10:00:00Z
サインアップ後のオンボーディング画面を改善して。3分以内に主要機能へ到達させたい。
既存デザイントークンは崩さないで。

## [IN-004] 2026-08-28T10:42:00Z  (Human Gate 回答)
DBのマイグレーションはやっていい。ただしロールバック手順を先に出して。
```

- jen-pmo は委譲promptに**該当する IN-xxx の原文を丸ごと引用**する（要約しない）。
- workerが「指示が曖昧」と感じたら、要約ではなく `.jen/inbox.md` の原文を読む。
- 行動監査（behavior-audit.md）は「メインセッションが要約して渡していないか」
  「inboxの原文と委譲promptの内容が矛盾していないか」を監査対象にする。
