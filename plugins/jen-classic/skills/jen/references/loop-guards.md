# Loop Guards & Context Hygiene (v3.4)

ループが「止まらない・空転する・汚れる」の3つを構造で防ぐ。

## 1. 無進捗検知（サーキットブレーカー）

進捗の定義: タスク台帳の状態変化（WIP→検収中など）、新しい検証結果、
または新しい確定情報のいずれか。以下は「無進捗」として数える:

- 同一タスクで実質同一の修正・アプローチが2回目 → その担当はSTUCK。
  同じ手を3回打つことを禁止し、担当替えか昇格に切り替える
- 2サイクル連続で台帳の状態が1つも変化しない → longrunのブレーカー作動。
  次のタスクへ進まず「外側リセット」（下記）へ

カウンタは進捗があった時点でリセットする。判定はPMOが台帳とboard.mdの
差分で機械的に行い、担当の自己申告（「進んでいます」）を根拠にしない。

## 2. 外側リセット（戦略の引き直し）

REJECTへの通常対応（差し戻し・昇格）は**内側ループ**の修正。
ブレーカー作動時はステップの再試行をやめ、**外側ループ**で戦略ごと引き直す:

1. 現在のアプローチを1行で言語化し「なぜ進まないか」を仮説化
2. mission.md に立ち返り、タスク分解そのものを作り直す
   （別アプローチ・別順序・スコープ縮小のいずれか）
3. 旧アプローチと変更理由を .jen/decisions.md に記録
4. 外側リセットは1ミッションにつき2回まで。3回目はHuman Gate

「同じ壊れたアプローチを、機構がないせいで繰り返す」ことを防ぐのが目的。

## 3. 空転検知（plan churn）

実行を伴わない計画の書き換えが2回を超えたら空転とみなす。
3回目の再計画は禁止し、現行計画の最小タスク1つを強制実行するか、
判断材料をまとめてHuman Gateへ。計画の完成度より前進を優先する。

## 4. コンテキスト衛生

衛生は往復両方で守る: **委譲時**はスコープを絞る(v3.6、下記+
references/context-scoping.md)/ **回収時**は結論のみ受け取る(本節)。

- **最小コンテキスト委譲**: 委譲promptに含めるのは
  Goal/AC/教訓ルール(最大3行)/必要ファイルパス のみ。会話履歴や
  無関係な経緯を流し込まない。ファイルパスは「全部読んで」ではなく、
  scoutが `.jen/codemap.json` からローカライズした対象のみに絞る
  (references/context-scoping.md)
- **結論のみ回収**: workerからPMOへの報告は結論＋証跡パスに限る。
  生ログ・全文出力は .jen/logs/ へ外部化し、台帳にはパスを書く
- **compactionに頼らない**: セッション圧縮で消えて困るルール・決定は
  会話内ではなく mission.md / decisions.md / lessons.md に置く。
  「さっき言った」は消える前提で設計する
- **境界の明示**: タスクをまたぐとき、前タスクの詳細を持ち越さない。
  必要なら台帳から読み直す

## 5. 停止時の報告義務（graceful failure）

ブレーカー・Human Gate・予算超過いずれの停止でも、必ず3点を報告する:
達成できたこと（部分成果と場所）/ 完了できなかった理由（確定・推測を分ける）/
回復に必要なアクション（人間がやること1〜3個）。
無言停止と「失敗しました」だけの報告を禁止する。
